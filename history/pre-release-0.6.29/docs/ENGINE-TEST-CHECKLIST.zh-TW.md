# C6 遊戲驗收清單 — 全部 NOT_RUN

**這是待執行清單，不是通過報告。** 每項記錄遊戲版本、裝置/控制方式、世界副本、Content Log、實際結果與畫面。Node替身不驗證Molang、坐姿、亮度、原生扣量或網路。

## 0. P0 顯示／本地化基線

**這一節先於所有功能驗收。只要出現 raw localization key，就停止後續功能測試。**

以遊戲語言分別切換簡體中文、繁體中文、英文並重開世界／資源包。打開創造物品欄、背包、配方書，至少抽查：酒館配方書、雪克杯、任一 Q2 基酒（例如落日餘暉）、固定雞尾酒、葡萄／桶／空杯、16色高腳凳與17款彩燈。任何名稱都不得顯示 `item.kaleidoscope_tavern:*.name`、`tile.kaleidoscope_tavern:*.name` 或其他 localization key。

另外驗證雪克杯使用按鈕、家具放置／坐下按鈕不顯示 `action.interact.*`。簡中不得由生成器重新混入明顯繁體品質詞（劣質／優良／精製／陳釀）或家具字樣（高腳凳／彩燈／潛行）。

本地靜態門檻：210個 runtime item 的 `minecraft:display_name` 不得以 `%` 開頭；每個 display key 與 interact button key 必須存在於 `languages.json` 宣告的所有語言檔；語言檔不得有重複 key。這些檢查只能防結構回歸，**實際客戶端仍需看到正確名稱才算通過**。

## 1. 載入與資料隔離

新世界啟用Cookery v1.0.6 BP/RP與C6 BP/RP，不開舊VisualLab/PoseLab。檢查11個block custom components、33新增家具物品、16座位entity、所有幾何/動畫/材質引用，不得有整包跳過或缺元件。指南、配方書仍獨立，Cookery原書、偏好與配方不變。兩個示範附屬按需測，全部啟用時43機器配方，核心仍41。

## 2. 全十六色高腳凳

`/function kt_c6_all_stools`只給16物件，需預留16欄。每色潛行點支撐顶面放置，核對完整底座/座墊/靠背/扶手/腳踏；下方必須允許完整支撐，上一格不夠空間拒絕。對4個玩家朝向擺放，凳面應與原作opposite-player規則一致。

空手點坐下，核對原生player坐姿、雙腿和Steve/Alex高度是否合理；記錄.8125候選是否需修。轉向跨過179/-179，檢查只轉上層、不卡轉/長圈、底座不跟著轉。第三人稱另一玩家應看到相同轉動。潛行離座、控制器/觸屏的離座按鍵、原生dismount是否卡牆都需單測。

兩人搶一席只能成功一人；已在船/馬上不切走原坐騎。有人乘坐時潛行回收與挖掘都拒絕；人離開後可回收。滿背包回收取消，不得只刪椅子。Creative放1扣1，取1返1。

離開區塊、重開世界後凳子仍在且只一個helper；occupied重連、死亡、跨維度不得留下鬼乘客。只移除helper，凳方塊稍後應重建；用命令換掉方塊，孤立helper要退人並消失、**不得補發一件家具**。未載入不能被當空氣誤清。

## 3. 全十七款彩燈

`/function kt_c6_all_lights`需17空欄。每款確認不是藍色換皮、各自薄片及UV正確。四方向尤其正背/側面、手持圖示透明背景均核對。暗室比較亮度15是否生效；不要求RGB染色光或紅石開關。

各色原生染料換型：消耗1個，保持朝向，換成該款自己的模型。相同顏色不扣。回收/挖掘得到1當前款，背包滿取消。重載後顏色/朝向不變。無色款由配方獲得，不測不存在的漂白功能。水浸/支撐移除自然落下目前不是已完成項。

原生合成冊驗證33配方：凳羊毛/鎖鏈/鐵錠豎列產1；彩燈兩排3鎖鏈+3燈籠產8，彩色加第三排3染料仍產8。

## 4. 聲波：只在空曠試驗場

**不要对準宠物、村民或建築內的生物，穿牆且可能傷害非敵對動物。** 以受控測試目標測32格、半寬邊界、後方不命中、斜向與垂直、穿牆。施用者當前20生命→基礎24、10生命→12，保持原生sonicBoom伤害與抗性/無敵結果；不是直接setHP。

拒傷目標不得仍被強制擊退。已有速度與新impulse相加，向上.28/水平.63；粒子16點與聲音只一輪。同線路另一玩家不得受傷/擊退；本包visual helpers、XP球不得被打壞。多於256命中要有可查限額診斷。

生存持一杯/整疊幽匿特調喝完，應原生扣1返1空杯，聲波回呼不得第二次扣/返。Creative也測，但不假設與生存完全一樣。原native傷害觸發血腥瑪麗等既有事件時不重複死亡回復。

## 4.5 螺絲起子／倒立效果

以生存玩家喝完一杯螺絲起子；16格膨脹AABB內的普通存活生物應被命名為 `Grumm` 並由原生彩蛋倒立。測試AABB角落、剛好邊界、邊界外、死亡生物、另一名玩家及本包座位helper；玩家自身與非mob不得被改名。重新載入後名稱應依原生實體名稱持久化規則保留。

Java原作另呼叫 `setCustomNameVisible(false)`；Bedrock Script API沒有通用直接對等項，因此需記錄名稱牌實際顯示方式。這一點在實機確認前仍是明示差異，不能只用Node替身判定完成。

## 4.6 莫希托／靈視效果

喝下莫希托後，用普通生物、另一名玩家與不同大小目標測試6格基礎半徑；目標新進入範圍時應取得60 tick Glowing。已經有 Glowing 的目標仍刷新時長，但不應重播靈視音效。等待下一個50 tick節點後確認持續刷新；離開範圍後不再續時，讓原生Glowing自行結束。

另以測試資料注入 amplifier 1／2，確認半徑12／18且2以上封頂18。測 AABB 邊界與角落，剛好貼面不得算相交；玩家自己、本包座位／視覺helper、死亡實體不得被錯誤發光。記錄原作 `effect.vision` 音效在單人／多人客戶端的可聽範圍，以及發光描邊對玩家與各類生物的實際表現。C6沿用5tick巡檢，因此pulse允許比Java精確tick最多晚一個巡檢窗口，但不可漏掉50tick節點。

## 4.7 下界特調／摸金校尉

喝下下界特調後，分別攻擊原作允許的骷髏系、殭屍系、豬靈系、衛道士／掠奪者與女巫，確認只有主手有物品且30%判定命中時卸裝。另測 creeper、evoker、玩家等非清單目標不得觸發；Bedrock 的殭屍化豬靈ID使用 `minecraft:zombie_pigman`。

用有耐久武器測掉落後應直接變成「僅剩1耐久」，不是只扣1耐久；已高度損壞的武器也應被改回僅剩1耐久。不可損耗物保留原樣。掉落必須是真實item entity，前40 tick任何實體拾取都被取消，第40 tick後恢復原生拾取。

注入掉落生成失敗，原主手必須回滾，不得吞物。另專測致死一擊：Java使用 `LivingHurtEvent`，Bedrock本適配使用可安全寫裝備／生物的 `afterEvents.entityHurt`，因此需要記錄致死時是否仍能穩定取得裝備、生成掉落；未實機前這一項是明示時序差異。

## 4.8 深水炸彈／黃銅之心／醇熱

分別喝深水炸彈與黃銅之心，兩者都應取得300秒醇熱。站著不衝刺時不得破塊；衝刺時用四個基本朝向撞測試牆，確認只處理玩家正前方一格、腳部高度到上方2格、左右各1格的3×3平面。

可破壞清單只允許：stone、granite、diorite、andesite、tuff、deepslate、netherrack、basalt、blackstone、end_stone。cobblestone、stone_bricks、end_stone_bricks與酒館家具必須保留。核對stone掉cobblestone、deepslate掉cobbled_deepslate，其餘目前明確映射為自身物品；這是Bedrock適配，不宣稱完整Java loot-table/附魔/工具規則。

同一tick即使撞碎多塊，也只追加一次1.2 exhaustion與一次盔甲／裸裝代價。有盔甲時在非空四槽中選一件：有耐久就扣1，最後1耐久應正常破壞；裸裝時每第5次「至少成功破一塊」才受1 generic傷害。注入掉落生成失敗時方塊應回滾，且不得追加exhaustion、盔甲損耗或裸裝撞擊次數。

效果自然到期應補600tick Hunger；食物值<=0且飽和<=0.01時也應提前移除醇熱並補600tick Hunger。實機需特別記錄 Bedrock exhaustion→食物／飽和的真實換算、方塊掉落、盔甲破損動畫／音效、多人同步及1tick衝刺巡檢成本。

## 4.10 c70eec 雞尾酒 cutout 第一組

依序擺放與手持黃銅之心、翡翠、教父、下界特調，四個水平朝向都觀察杯身內外面、液面／裝飾薄片、透明邊緣與遠近距離排序。確認相較舊 blend 不再出現明顯混素／半透明疊色，同時不能因 single-sided cutout 遺失原作有定義的面。

本批 source 嚴格限定為 render_type translucent→cutout 與 plan 指定 element shade true→false；PNG、座標與UV未變。Node/Python只能驗證這個結構契約，**真實 alpha-test 邊緣、MSAA／手機 GPU、第一/三人稱 item_visual 仍需實機畫面**。

## 5. C5 及之前功能回歸

至少走一次種植→壓榨→釀造→Q4投料→拿起雪克杯→原生長按/鬆手→倒入已放空杯→擺取特調→飲用。16空桶/空杯交換保留15；退藥水保留effect/delivery，不變水瓶；本輪不得讓家具beforeEvent吃掉原機器互動或其他包已取消事件。

原生長按是否真的觸發、remaining ticks、111tick watchdog、Steve/Alex手腕與杯嘴、不同FOV/手機/控制器、透明排序仍是未驗收門檻。指南切換fallback只驗fallback，不算native成功。牛奶/死亡清自訂持續效果、離線暫停、原生返瓶/返杯也需實機。
