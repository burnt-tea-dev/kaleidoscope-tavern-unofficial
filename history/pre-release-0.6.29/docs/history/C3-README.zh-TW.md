# 森羅物語：酒館 C3 — 桌上雪克杯、雞尾酒與調酒附屬接口

**功能開發版，尚未在 Minecraft／Realms／BDS／手機實機驗收。不是完整移植，也不應用於主存檔。**

C3 保留 C1／C2 的釀造、種植、原生酒效、逐瓶品質展示、獨立指南與真實 Cookery 前置；新增可實際執行的桌上調酒、杯具保存、特調資料與附屬配方能力。沒有重畫、覆寫原作美術。

## 安裝

先備份，使用新測試世界。依次啟用使用者提供的 **Cookery v1.0.6 BP/RP** 及 C3 BP/RP；酒館資源包放在 Cookery 上方。不啟用舊 C1/C2 或 A17 VisualLab／PoseLab。C3 套件 UUID 延續 C2，版本為 **[0,3,0]**；這是套件更新，不代表實際存檔升級已測。

Cookery 真實依賴未變：BP `10f37ae2-9ccf-435f-b34b-0eec8191cd94`，RP `c89dc8df-c3fc-4bc8-8bd0-527abba76681`，內部版本皆 `[1,0,6]`。Script API沿用 `@minecraft/server 2.7.0`、UI `2.0.0`，與上傳Cookery實包一致；**不是本輪最新API或兼容性認證**。工程格式沿用 `1.26.50`／既定26.51測試目標。

C3沒有 `player.json`、全域UI覆蓋、beta模組或新的實驗開關要求；不能據此宣称成就、Realms或引擎載入已驗證。

## 桌上調酒操作

1. 執行 `/function kt_c3_kit` 取得本輪測試物品。只給物品，不清空／建造世界，請預留背包空間。舊`kt_c1_kit`、`kt_c2_kit`仍在。
2. **潛行手持雪克杯，點完整支撐方塊上表面**放置。世界中顯示原作模型，消耗一個實際雪克杯。支持清單／標籤沿用瓶具支撐規則，不自動接受所有外包桌面。
3. 每次手持Q4或以上基酒點雪克杯，倒入一瓶、立即返一個酒館空瓶。每槽只存一份，最多三槽。
4. 三槽全滿，**空手點一下開始，再空手點一下停止**。只有開始的玩家可以停止；HUD每5tick更新，音效每10tick播放。判定使用伺服器tick，不以現實毫秒計算；網路延遲及手機手勢需實測。
5. 成品可以**手持空雞尾酒杯點雪克杯**取出；16杯只扣1，剩15。
6. 或先潛行放置空雞尾酒杯到雪克杯水平相鄰的位置，再空手點該杯倒入。杯子先前已被放置消耗，不會再扣第二個空杯。相鄰若有兩個已完成雪克杯，拒絕模糊選擇，改用手持接杯。
7. 潛行手持成品可擺一杯；空手或正常破壞取回原杯，特調的顏色、效果與原料品質都保留。空杯旁有可倒成品時，**潛行空手點杯**可取回而不倒酒。

### 停止時間

| elapsed tick | 結果 |
|---:|---|
| 0–18 | 不製作，材料全部保留 |
| 19–68 | 神秘雞尾酒 |
| 69–88 | 特調雞尾酒 |
| 89–98 | 嘗試固定配方；未匹配則特調 |
| 99起 | 神秘雞尾酒；111tick自動結束 |

原作規則來自上傳JAR反組譯及固定1.21.1源碼參照，詳見`docs/C3-SOURCE-NOTES.zh-TW.md`。原作手持操作、原生搖手動畫／PUT事件綁定仍未接，不能把兩次點擊適配說成1:1操作還原。

快速測白色佳人：Vodka Q4＋雷司令乾白 Q4＋螢花釀 Q4，三瓶各一個；於89–98tick停止。

### 退料與中斷

未開始或取消計時後，拿空酒瓶點雪克杯可取回最後一份原品質基酒，**同時消耗一個空瓶**。不能空手拿回完整酒又保留先前已返的空瓶。附屬沒有容器的普通材料可潛行空手退回。

離開6格、切換維度、死亡、退出或區塊卸載會取消未完成的計時；已投的三份材料仍在。重載不離線補算，也不自動在神秘／特調之間選結果。成品一旦完成會保存輸出與特調快照；附屬被更新或卸載不能把同批產物換成另一配方。缺少產物包時拒絕取出，不扣成品。

裝料／有成品的雪克杯不能拆除。材料／杯子裝不下時取消而非丟在地面。交易在普通API例外時回退物品與世界DP，但**不提供引擎崩潰級跨背包ACID保證**。管理員`/fill`等外部替換可能留下需恢復的失配DP；不自動刪掉玩家結構。

## 效果真實狀態

**十二固定雞尾酒＋神秘雞尾酒的原作效果都是Java專屬；本輪沒有實作它們的特殊效果。** 可以製作、擺杯、取回，原生food已設定飲用返杯，但不會獲得那些尚未移植的能力，也不會被替換成速度／力量等其他buff。

特調中的既有原生效果則已接入 `addEffect`；同時保留微醺等尚未實作的條目並在診斷標記。C2既有24酒類的原生酒效保持。查`docs/C3-EFFECT-COVERAGE.json`，不要把「14種成品可做」等同「14種效果已做完」。

特調不可堆疊，以自身ItemStack dynamic property保存資料；其他固定杯可堆16。擺放及取回採完整clone，不丟失payload。沒有有效payload的特調（例如直接`/give signature_cocktail`）拒絕擺放／施效，應由雪克杯真正生成。

原生food負責消耗與返空杯，效果回呼**不扣第二杯、不返第二個杯**。整疊、滿背包、Creative、最後一杯、中斷取用仍需引擎實測；Node mock沒有模擬這些原生機制。

## 資料與程式入口

`core/mixology.js`為純規則、容量、品質、時窗、效果合併、RGB與schema檢查；`bedrock/mixology.js`接事件、交易、世界保存、session、RGB helper；`data/mixology.js`由锁定JAR配方／tag／效果表建置。`kt:shaker/維度/x_y_z`與`kt:cup/維度/x_y_z`使用各自schema1，不改舊機器或瓶堆保存键。特調payload鍵為`kaleidoscope_tavern:cocktail_data`。
