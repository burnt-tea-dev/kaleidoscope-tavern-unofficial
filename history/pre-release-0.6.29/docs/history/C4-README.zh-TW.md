# 森羅物語：酒館 C4 — 可攜調酒與沉浸動作接線

**這是功能開發測試版，尚未在 Minecraft／手機／Realms／BDS 實機驗收。** C4 保留 C1–C3 的釀造、栽培、原生酒效、逐瓶品質、杯具、獨立指南及附屬 API；本輪不是擴大配方數，而是讓「投料—拿起—搖動—倒入已放空杯」成為連續流程。

**仍採手持兩次使用起停，不是原作原生長按／鬆手。** 沒有把帶資料的工具偽装成食物、弓或投擲物去模擬長按；不寫 player.json。第一／第三人稱掛點、動畫融合與原生按鍵事件均須遊戲驗收。

## 安裝與資料相容

先備份，使用新的測試世界。啟用你提供的 **Cookery v1.0.6 BP／RP**，再啟用 C4 BP／RP；酒館 RP 位於 Cookery 上方。C4 包含 C1–C3，不同時啟用舊 C1/C2/C3、A17 VisualLab 或 PoseLab。

套件 UUID 保留，header/module版本為 **[0,4,0]**。原世界機器／杯具存檔鍵與schema1未改；新增可攜資料鍵為 `kaleidoscope_tavern:shaker_data`，schema1。可攜工具內含自己的輸入、結果、revision與識別token，不把整杯內容存在玩家全域變數。**真實世界升級仍未測。** 請先清空C3桌上正在計時的session，並在副本世界驗證。

Cookery依賴仍由實包鎖定：BP `10f37ae2-9ccf-435f-b34b-0eec8191cd94`，RP `c89dc8df-c3fc-4bc8-8bd0-527abba76681`，版本[1,0,6]。不散布或修改Cookery本體。Script API沿用工程的 `@minecraft/server 2.7.0`、`@minecraft/server-ui 2.0.0`，格式1.26.50；不是本輪聲稱最新版本或實機兼容認證。

## 建議實測路線

```mcfunction
/function kt_c4_kit
```

本函數沿用C3給物套件，只給物品、不搭建／清空世界。請空出背包和桌面。

1. 潛行手持空雪克杯，點完整支撐方塊上表面放置。模型由原作完整骨架helper顯示，選取／碰撞和資料仍由方塊承擔。
2. 依次倒入 **伏特加Q4、雷司令乾白Q4、螢花釀Q4**。每次成功才開合杯蓋、出氣泡、播放倒空瓶聲；立即返還一個空酒瓶。失敗沒有假成功動效。
3. **潛行＋空手點雪克杯上表面**拿起。三份原品質原料仍在這個不可堆疊工具裡，桌面不留下第二杯或資料副本。
4. 手持點一次使用開始搖，第二次使用停止；潛行使用取消。配方窗口仍為89–98tick。預設沒有精確讀秒，要測窗口可開自己的酒館指南 →「沉浸／計時輔助」。
5. 製作完成後，先在完整支撐上放一個空雞尾酒杯，再換回雪克杯，對準該杯使用。**12tick過場結束才把成品寫入杯子、清空雪克杯。** 已放杯已在放置時消耗，不再扣背包第二個杯子。
6. 中途切換快捷欄、走出6格、切換維度或杯子被外部替換，取消本次倒酒，保留仍存在的工具內容。請回到空杯前再試。
7. 完成或半途取消的雪克杯也能潛行放回桌上，繼續C3的桌上兩次點擊、手持容器領取或鄰杯服務流程。

### 退料和工具規則

基酒投料會先返空瓶，所以退料仍須手持一個空酒瓶，點桌上雪克杯，取回最後一份原品質基酒並收回該空瓶。**無容器的附屬原料**改為「潛行空手點雪克杯側面」退一份；上面才拿起整杯。普通點擊仍用於桌上搖杯，避免新攜帶手勢讓既有附屬材料無法退回。

直接破壞裝料／有結果的雪克杯仍拒絕；請以潛行空手拿起，而不是強拆。Creative所有材料和容器交易也守恆。已有結果不能再次搖成另一結果；按錯不會免費重抽。

原作窗口未改：0–18不製作、19–68神秘、69–88特調、89–98固定配方／無匹配為特調、99以上神秘、111tick自動結束。這是伺服器tick，不是現實秒；20TPS時12tick約0.6秒。

完整對照在 `docs/C4-IMMERSION-PARITY.zh-TW.md`。原 PUT 檔、原模型與原PNG逐位元組保留。手持搖動的振幅／頻率及左右臂數值來自既有原件；Molang的sin使用度數，所以明確換算。新增桌面晃動、手腕錨點、12tick／65°倒酒、液滴插點是Bedrock適配，不是 recovered source animation。

`previews/C4-motion-preview.gif` 和 `C4-put-keyframes.png` 是本地原模型動畫採樣，**不是Minecraft截圖**。GIF不含玩家模型、滴流、音效或真正引擎插值，只展示相對骨架運動。波形不等於按鍵輸入已被驗收。

## 狀態安全與視覺清理

可攜工具在空閒、搖動、倒酒時使用三個內部ID顯示原模型；只在同步校驗後交換，帶相同工具資料。主物品是`kaleidoscope_tavern:shaker`，另兩個`shaker_active`／`shaker_pouring`不應被當成額外配方產物。

切換手持或死亡取消session；掉出的暫態工具被另一玩家取得後可恢復普通工具。**不會因找不到工具就在玩家背包重新生成一份。** 重新登入／收到孤立暫態工具只復原已有內容，不補算離線時間。搖杯期間修改同ID工具的payload，也會判為衝突而停止，不能覆盖另一杯。

倒酒時預約杯位，其他本包取杯／倒酒先拒絕。完成時重查原杯狀態與revision、手持快照、維度、距離及產物存在。普通API例外嘗試回退；不保證引擎硬崩潰跨背包／世界DP的ACID。

非權威音效／動畫層不寫背包、配方或機器資料。missing動畫、粒子或音效例外記入有上限的診斷；不因此撤銷已成功交易。helper按錨點去重，重載後清孤兒，未載入區塊不當作空氣。候選Molang／原生shader失效仍需Content Log定位，不能由mock自證。

## 指南、附屬與既有功能

指南／配方書完全獨立於Cookery。C4的輔助開關只寫`kaleidoscope_tavern:timing_assist`，不動廚房偏好。內建機器配方仍41；API v1及schema不改。兩個獨立示範依賴更新到C4，不預設安裝；同時開兩個共43配方。

手持調酒開始時保留配方快照；附屬更新／卸載不會替換該批結果。未知附屬產物不硬套本包空杯渲染：放回桌上，使用其指定容器領取。原生藥水資料與Java專屬效果仍未做，沒有因C4更好看就視為完成。
