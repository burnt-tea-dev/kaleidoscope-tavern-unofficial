# 森羅物語：酒館 C2 — 種植、逐瓶品質展示與原生酒效

**功能程式開發版，尚未在 Minecraft 引擎／Realms／BDS／手機驗收，不是完整發布版。** C2 包含 C1 的獨立酒館書、附屬 API 與釀造核心，不必同時安裝 C1。

## 本輪真正新增

| 系統 | C2 程式範圍 | 仍有的差異 |
|---|---|---|
| 三種葡萄種植 | 裸藤架、普通／冰／金葡萄藤及果實，7個行為方塊；藤0–3、果實0–5；七種連接形狀、自動蔓延、下掛結果、骨粉、上蠟／刮蠟、剪藤及剪收 | 沒有野生生成、Java適溫加速、水浸；十字碰撞暫用包圍盒 |
| 逐瓶品質擺放 | 24類釀造飲品含醋，93個原作數量外觀；同類不同品質可放一起，空手取最後一瓶，拆堆返全部原品質 | 不含西瓜汁、雞尾酒與附屬自訂新模型；支撐採清單／標籤，移除支撐暂留可取回瓶堆 |
| 原生酒效 | 24份原作效果表，14種原生效果、109筆品質效果條目；各項獨立機率，秒×20轉tick，保留amplifier | 5種Java專屬效果仍不生效，在指南與診斷明確標記，不用猜測buff替代 |
| 品質1修正 | **Q1也可飲用**；例如Wine Q1有30秒噁心 | C1把Q1禁止飲用是錯誤，已修正；原生返瓶需實機驗證 |
| 葡萄食用 | 四種葡萄物品使用原作2營養、0.5飽食修正、alwaysEdible | 原生食用／返瓶消耗由引擎執行，mock沒有替代引擎 |
| 獨立指南 | 新增種植／擺瓶操作頁，以及24頁六品質酒效表，可搜尋、書籤、切換語言 | 核心配方仍23釀造＋6壓榨；合成配方由原生合成冊顯示並在指南說明 |

原作模型與貼圖沿用 A17，不重畫、不以普通方塊代替已完成美術。C2新增7個種植方塊和24個酒瓶展示方塊，正式BP累積35方塊、159物品、14個機器渲染helper。

## 安裝、依賴與版本

- 使用已提供的 **Kaleidoscope Cookery v1.0.6** BP／RP 作必要前置；它不隨本包重新散布。
- 匯入 `Tavern-C2-Gameplay-DEV.mcaddon`，在新的測試世界啟用酒館 BP／RP；酒館RP放在Cookery上方。
- 不要同時啟用 C1、歷史 A1–A17 VisualLab 或 PoseLab。C2的UUID與C1一致，版本提高至 **[0,2,0]**，會作套件更新。
- 有測試附屬需求才另啟用 `Tavern-C2-Extension-Demo-OPTIONAL.mcpack`。API仍是v1，不改傳輸／資料契約，Demo只更新套件依賴版本。
- 仍沿用工程 `1.26.50` 格式與既定26.51驗收目標。Script API維持Cookery實包的 `@minecraft/server 2.7.0`、`@minecraft/server-ui 2.0.0`，**不是新的最新版本聲明，也不是已在該版本載入成功**。
- 沒有 `player.json`、全域UI覆蓋或beta依賴；不宣稱成就／Realms兼容已證實。

機器保存仍用C1 schema1；C2瓶堆使用獨立schema1世界屬性，植物狀態存在方塊排列。沒有修改舊機器保存鍵。雖然設計上可讀C1資料，**真實存檔升級未測，先備份，不在主世界直接部署**。

## 開發測試

```mcfunction
/function kt_c2_kit
```

只給物品、不建造／清空世界。先預留背包空格。包含C1套件、6葡萄藤、24藤架、64骨粉、剪刀，以及不同品質Wine測試瓶。

### A. 從種植開始

1. 原版 **藤蔓＋甜莓→1葡萄藤**。這是移植版新增的取得配方，不是Java原配方，也不是野生生成。三個葡萄藤直列合成8藤架則沿用原作。
2. 將藤架放在泥土類、冰／雪塊、地獄石／岩漿塊上，再手持葡萄藤使用。分別種出普通、冰、金葡萄；青提不是第四種作物。
3. 向上搭藤架，再向旁邊延伸。成熟藤依序找上、東、西、南、北的未上蠟裸架；向上新藤從age0開始，側邊新藤從age3開始。
4. 所有可延伸位置都檢查完後，下方有空氣才會結果。成熟果實age5用剪刀收割：3同種葡萄，另30%機率1–2青提；果實消失，藤架稍後可重新結果。
5. 骨粉可推進；無空間／已成熟果實時不消耗。蜂巢給裸架上蠟以阻止蔓延，斧頭刮蠟；剪刀剪藤會保留裸架並返回葡萄藤。

植物自然成長使用原生random-tick回呼；0.25是每次回呼的機率，**不是每秒固定長25%**。冰／金的Java氣候0.8加速未適配。普通破壞成熟果實產1–2主要果實，另30%一個青提；未成熟不產果實。

採收會先檢查背包；放不下則不採收、不損耗工具。剪刀／斧頭保留名稱、附魔與耐久，並處理Unbreaking機率；最末耐久會使工具消失。帶自訂資料的葡萄藤／骨粉等原料拒收，不清除資料後強行使用。

### B. 釀造與喝酒

水果投入壓榨桶，跳踩8次滿1000mB，空桶取汁；4桶同類汁灌滿3×3×3酒桶。Wine不加其他材料；潛行空手關蓋，酒嘴手持空瓶取酒。其餘操作與C1一致。

**品質1可以喝。** Wine Q1的來源效果是噁心30秒；Q3的生命恢復80秒、Q6的生命恢復540秒／amplifier1已接入。每项依原作機率獨立抽選。微醺等Java專屬效果仍未實作，不能把「可喝」等同「全部酒效已還原」。

程式僅在 `onConsume` 呼叫 `addEffect`，不再扣第二瓶或手動返第二個空瓶。原生 `food.using_converts_to` 承擔消耗／返瓶；**整疊、滿背包、最後一瓶、創造模式等原生行為仍須引擎驗收**。

### C. 擺瓶與品質回收

1. 潛行手持酒，點石頭等允許支撐方塊的上表面擺第一瓶。
2. 再拿同種酒點瓶堆，加入下一瓶；可以混合q1、q3、q6，不能混不同酒類。
3. 空手點瓶堆取回最後放入的一瓶；破壞整堆則返所有原始品質。
4. 白蘭地、佳麗釀、落日餘暉上限3，其餘本版釀造飲品4。超量、背包满、狀態衝突會取消，沒有多扣／多領。

支撐判定不使用仍被官方標示為預發布的 `Block.isSolid`。目前支援明確列出的完整石材、木材、泥土、羊毛等，及帶 `kaleidoscope_tavern:bottle_support` 標籤的自訂支撐；不是自動支援每個Cookery桌面或台階。清單在 `core/bottle-support.js`。外部作者應只給全頂面的方塊標籤並實測放置高度。

Creative擺瓶也消耗真實一瓶，取回返原瓶，避免展示器變成複製機。支撐消失時暫留浮空瓶堆供取回，不自動丟物。`/fill`、`/setblock`、其他包替換會繞過交易；狀態／方塊不符時停止操作而保留DP。

## 指南與附屬

兩本書仍完全獨立於Cookery。主機配方與酒館配方書用同一registry，不注入廚房指南、語言或已學配方。八個手寫指南條目＋24個來源酒效表，以及29機器配方頁均可搜尋。部分簡中頁目前沿用繁中操作文案，完整人工本地化仍在後續範圍。

附屬API1原有酒桶／壓榨配方與指南頁不變。附屬可繼續使用Cookery米等已載入材料。C2的24族擺瓶及內建酒效不會自動套到附屬任意新物品；其美術／食用腳本由附屬提供。詳細契約見 `docs/EXTENSION-API.zh-TW.md`。

## 驗證的真實邊界

`docs/TEST-RESULTS.json`、`STATIC-VALIDATION.json`、`REBUILD-REGRESSION.json`為本輪實際結果。保留C1的核心／事件測試，新增種植、原品種掉落、工具資料、混品質、並發、異常回退、原生效果表和新增書頁檢查。

有一個mock整合案例確實把**種植採收33葡萄→4桶壓榨→釀造→擺瓶→取回→效果回呼**串起來，但它不執行Minecraft，不模擬原生食物扣量／返瓶。Cookery測試只載入其兩個API模組到本地事件測試環境，不是整包啟動。

```text
python tools/build_runtime.py
python tools/validate_runtime.py
python tools/test_c2.py --cookery-reference "實際Cookery BP資料夾"
python tools/audit_rebuild.py
python tools/package_c2.py
```

省略 `--cookery-reference` 會明確跳過可選Cookery原模組測試，其他測試仍執行。舊 `test_c1.py`、`package_c1.py` 名稱在C2保留為相容轉呼叫入口。

## 待補與限制

- Java專屬酒效：微醺、high_heels、grass_stealth、vision、bloody_mary；沒有猜測替代。
- 雪克杯／雞尾酒、燃燒瓶、西瓜汁特殊酒嘴、下方容器自動接酒仍未啟用。
- 野生生成、氣候加速、水浸、精細聯集碰撞、自然爆炸／活塞破壞掉落未還原。C2植物與展示器和C1機器同採防爆／不可推動策略。
- 家具乘坐／連接、文字渲染、容器展示、完整手持動畫和其他渲染適配未完成。
- 遊戲引擎、手機、Realms、BDS、真實存檔升級與原生返瓶尚未驗收。

`--production`仍拒絕匯出；這些是發布門檻，不妨礙繼續開發與新測試世界驗證。
