## Project behavior

- Java mechanics are authoritative. Preserve board left/center/right and legacy top positioning; the owner's justified/distributed and vertical alignment extensions remain intentional.
- Guide work follows `docs/GUIDE-STANDARD.md`: independent Tavern and optional Cookery entrances use the same shared projection, seven sections, child groups and individual entries. Addons provide data, not parallel UI implementations; do not flatten or rename navigation.
- Preserve quiet immersion: successful placement/pickup/machine use has no added Actionbar announcements. Source-backed rejection feedback is one-shot; automatic effect and Jade-style barrel text is opt-in. Preserve shaker graphics and optional brewing status without polling ordinary messages.
- Graphical shaker/eating packets may use the existing bounded Actionbar event transport; do not clear the shared channel or add unsolicited human-readable text. Effect icons keep their separate bounded event-only zero-duration title route, optional existing UI Queue/single observed embedded router, and standalone operation independent of managed-server. Do not join third-party router elections or replace native/foreign effect controls.
- Optional effect sprites remain in their addon RP and absent effects are inert. Registered UI uses owned namespaces and fully typed controls; do not redefine hud.root_panel from _ui_defs. Mount optional panels through namespaced variables with typed empty defaults. UI changes run the pinned Mojang native-root preservation regression. Effect details open only on explicit guide sneak-use. Static routing, BDS and rendered client acceptance remain distinct.
