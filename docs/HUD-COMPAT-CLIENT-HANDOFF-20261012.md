# Dot：本輪 HUD 實測入口

本輪候選是 T148／G129／W125，私有料理保持 1.0.32。部署成功後以 luosen 正常提供的完整家族實測；公開下載與伺服器仍須逐檔核對。先前 G126 單包 no-clear 影片及 T147 HUD200 影片的原始範圍不變，不能當本輪 LIVE 的畫面驗收。

## 本次要分辨的缺陷

T147 與 G128 把各自圖形及 root modifications 放在同一路徑 `ui/hud_screen.json`，luosen 的酒館資源包在煙火之上；兩包的原生訊息過濾亦不同。即使單包成功，完整堆疊仍可能漏掉另一側的圖形工廠。本輪把兩個 renderer 移入獨立已登記命名空間，兩包共用同一個可選掛載橋接，並共同排除內部封包。靜態檢查驗了原生 29 個控制、兩個命名空間、缺包空面板及相同橋接，尚未執行客戶端 renderer。

## 一次正常玩家流程

1. 重新加入更新完成的 luosen，正常接受伺服器資源包。保留客戶端 content log，先確認快捷欄、準星、飢餓／血量及 AMW 現有 HUD 均存在。
2. 以正常玩家實際食用煙火食物，完整吃一份，再重吃並中途放開／換槽。錄下 102 像素原圖進度條、黃轉綠、物品圖示及停止後自然消失；不可用人工封包播放代替自然食用。
3. 正常開始調酒，核對槽位、游標及進度；停止後回到煙火食用。另以正常飲用帶出酒館／世界名酒效果圖示，確認它們不使原生與 AMW 控件消失。
4. 在圖形結束後觸發一個其他 addon 的普通 Actionbar 提示，核對它仍顯示且不被結束流程清空。若同時寫入 Actionbar 才出現缺幀，記錄具體 addon、時間和封包來源，與本輪掛載／命名空間問題分开處理。

最小回報包含實際 LIVE 版本、客戶端版本／裝置、GUI 比例／輸入方式，以及一次上述流程的影片和同期 UI 錯誤原文。先確認完整堆疊下兩個圖形都能掛載，再針對真實失敗縮小來源；不反覆用隔離成功影片代替 LIVE 驗證。

## 保留的邊界

Minecraft 的 Actionbar 是共享通道。圖形掛載修復不保證兩個 addon 同一 tick 都成功覆寫該通道，也不能控制第三方完整替換 HUD 的行為。本輪未更改圖形時序、食用結算、普通訊息或第三方包。CI、BDS 與存檔通過後仍保留 `client=false`、`production_ready=false` 及 `pending_client_acceptance`，真人回報須另記原始候選／場景。
