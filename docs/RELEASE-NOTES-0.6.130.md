# 0.6.130：展示維護、原生效果與舊物品升級

本批從已合併的 T129 `9752aaee5cb6f0d0460cb9f9c8ab3424f975c1e4` 繼續修復，
配對 World Liquor 0.1.107。三路代理分別處理效果 API、展示效能及語言路由，
再作交叉審查。原有雞尾酒配方、判定時鐘、HUD 插值與個人音量功能沿用。
這是測試候選；實際客戶端畫面、整體 FPS／耗電及私有 LIVE 仍未驗收。

## 一、畫面與遊玩效率

斜酒架與吧台酒櫃現在每次整櫃同步只搜尋一次附近展示實體，再按槽位分組。
相同 owner 在每批維護中只同步一次；實體種類、位置及朝向已正確時，不再
重複呼叫屬性、旋轉與傳送 setter。仍使用原來的四向位置、斜架 22.5 度
傾角、模型與數量。每批 128 個 handle 的上限與持續向前的游標保留。

第一個槽位失效時仍會同步其餘槽，避免漏修缺失展示；酒櫃 owner 尚未載入
時保留其 helper，不把未知狀態視為方塊已拆除。附近的缺失、重複、錯誤
類型及位置偏移仍可修復。超出 owner 兩格搜尋圈的遠距 helper 是既有
邊界，本批沒有宣稱任意距離的修復。

這些數字不是 Minecraft FPS、TPS、CPU 或耗電量測。

## 二、可用原生 API 補全

醇熱的快速處理現在按原作事件順序結算 Hunger、碰撞及飢餓／飽和度解除。
移除等到五 tick 維護輪次才解除的延遲，避免食物耗盡後再多破壞方塊；
站立時也會解除。較短、較強的狀態結束後，仍保留合法的較長、較弱狀態。
交叉審查另修正提前寫回造成感知／草叢潛行漏判一次，以及同時到期的
強弱醇熱重複給予 Hunger；相鄰效果已到的週期會先結算且不重發。

Bloody Mary 現在接受已支援生命狀態追蹤的非玩家 LivingEntity。來源明確
帶此效果的酒類經既有投射入口命中生物後，可在其原生擊殺事件按原作
`floor(victim.maxHealth / 3)` 回血。只有這個已實作效果開放此範圍，
不把尚未適配的感知、步高或其他效果一起放寬；有血量的載具不算活物。

真正的 BDS 1.26.52.3／Script API 2.7.0 場景中，狼取得效果後擊殺
10 HP 的牛，HP 由 2 增至 5。這是無玩家場景的原生傷害／死亡事件驗證，
不是玩家實際飲用或全效果驗收。來源、probe 與完整限制見
[效果 API 記錄](COCKTAIL-EFFECTS-API-20261008.md)。

同次能力檢查的 skeleton、zombie、pillager、piglin、wolf、armor_stand
均沒有可用 `minecraft:equippable`。因此摸金移除這些原生怪物裝備仍受
目前 API 限制；沒有用猜測掉落物或測試替身掩蓋這個差異。

## 四、舊雪克杯的可讀資料保留

早期 `shaker_active`／`shaker_pouring` 升級為現行雪克杯時，會在寫入
背包前複製並核對名稱、原生 RawMessage lore、冒險模式破壞／放置清單、
保留死亡／鎖定設定，以及當前 BP UUID 範圍內可讀寫的 dynamic properties。
只更新完整匹配的程式自有 lore。複製失敗或靜默資料丟失不寫原槽；寫回
失败會回滾並核對原物品。損壞的一格不阻止後續正常舊杯升級。

`ItemStack.typeId` 唯讀，`clone()` 無法變更 ID；因此本修補不是任意 NBT
或另一 BP UUID 私有資料的無損轉換。另一 namespace 的測試鍵仍屬目前
BP scope，不能作為跨包私有資料保留證據。出現目前兩個舊定義不應有的
inventory、durability、enchantable 或 dyeable 元件時，會保留原物品。
原生 API 定義見 [Microsoft ItemStack](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/itemstack?view=minecraft-bedrock-stable)。
