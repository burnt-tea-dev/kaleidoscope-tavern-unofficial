# 0.6.129：雞尾酒流程、提示與效果修復

本批以 `d295390e1023ec0a8f38c82ebbfd1ddc1eacb509` 的 T128 為起點，
按調酒流程、保存、呈現與效果分段修復，再整合成一個版本。World Liquor
0.1.106 的 BP/RP 精確配對 T129；既有 UUID 與 Grilling 2.8.117 配對保留。
這仍是測試版，沒有宣告完整 Java 一比一或真人畫面驗收。

## 一、原料、份數與操作

- 投入資格依原作雞尾酒原料標籤及明確註冊的附屬原料／配方判定。
  安裝了某個物品不再自動代表它可投入雪克杯；原有低品質提示仍保留。
- 空瓶等容器先嘗試加入背包，再扣除手上那份原料；背包當時已滿則掉落
  容器，符合 Java 的先後順序。失敗保留原料、庫存與杯中狀態。
- 創造模式放置雪克杯遵循現有 `placementTake` 規則，不再固定扣一個。
- 補上潛行、空中揮擊清空雪克杯的路徑：清掉全部三份原料及成品，不退料。
  Script API 沒有 Java `LeftClickEmpty` 的完整命中資訊，因此先排除視線中
  的方塊／實體；真正的滑鼠與觸控輸入仍待客戶端驗收。
- 雪克杯與 15 種杯子的選取／碰撞範圍、零硬度及活塞破壞設定依 Java
  方塊來源修正。客戶端選取手感與實際活塞／爆炸事件仍須實景驗收。

已正確的 12 個固定配方、16 個原料分類、現行效果來源及三份可重複原料
規則保留。時間帶仍為 0–18 tick 取消、19–68 神秘、69–88 特調、89–98
固定配方或特調、99 起神秘；超過 110 tick 自動完成。未以畫面動畫重寫時鐘。

## 二、雪克杯保存的修復與界限

新版將放置中的完整外層雪克杯存入既有原生 entity ledger，延續手持杯的
名稱、外部 dynamic properties 與自訂 lore。放置、投入、取回與破壞共用
交易與回滾；自然破壞將原生記錄與掉落納入可回滾交易，一般掉落成功後
才移除已清空的 helper，失敗則保留／恢復記錄與仍可復原的原方塊。
創造模式與 `doTileDrops=false` 的有意不掉落仍依原規則清理。公開狀態
遺失或非法時，仍有原生 carrier 就拒絕空杯回退並保留復原資料。

原料本身仍採可驗證的既有身份／藥水狀態。具名、自訂說明、外部 dynamic
properties、鎖定等已辨識不支援的原料資料在投入前拒絕，不能把這項外層
保存修補稱為「所有原料 metadata 無損」。
早期 `shaker_active`／`shaker_pouring` 改 ID 遷移，以及已在舊資料中遺失的
附加欄位，也不在無損保存宣告內。

本批曾實作物品內部三格原生容器，但實際 BDS 1.26.52.3／SDK 2.7.0 否決
了這條路線：缺重量元件會出現 `InvalidContainerError`；合法重量上限 64
只容一瓶重量 64 的藥水。缺 `storage_weight_modifier` 的自訂容器還會在
clone 後失去內容，補齊該元件也不能解決三瓶容量。此方案不進入發布 runtime。
診斷見 [原生能力記錄](../data/native-shaker-storage-capabilities-20261008.json)，
容量規則見 [Mojang 官方元件文件](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/itemreference/examples/itemcomponents/minecraft_storage_weight_limit?view=minecraft-bedrock-stable)。

## 三、調酒呈現與可讀性

- 雪克杯進度游標在相鄰 tick 間線性移動，並將過期進度的本地消失時間
  縮短到 0.1 秒；只修改 Tavern 自有進度控制，原料列期限保持原設計。
- 固定雞尾酒與特調物品說明取實際效果資料，顯示保證觸發的效果、等級、
  持續時間及正負面顏色。瞬間效果不顯示假倒數；超過原生 lore 容量時
  顯示尚有幾項效果，完整效果 payload 保留。
- 杯內清單採原料分類顏色與可還原身份的本地化名稱；成品列取成品名稱。
  只更新完整匹配的程式自有 lore，玩家追加的說明不被覆蓋。
- 指南補齊實際效果與操作說明，釐清三份原料可以重複、順序不影響配方、
  提早放開取消及清空操作。獨立指南和 Cookery 投影共用資料與七個入口。
- 從 Loyallay 公開版吸收可調整呈現的設計，以獨立實作加入指南「語言與音量」
  設定。玩家自己的搖酒／完成音效可選較小、原音量、較大；正常為預設，
  旁觀者音量與原音效路由保持原設計。取消表單不寫設定，儲存失敗會回滾。

第三方包的來源、優點與未解決差距見
[Loyallay 1.0.1 公開包審查](THIRD-PARTY-TAVERN-REVIEW.md)。未複製其程式或素材。

## 四、效果適配

烈焰衝撞改用原生 `setblock ... air destroy` 處理來源白名單內的方塊，讓
原生掉落與 `doTileDrops` 生效。保留原來的 3×3 範圍及一次飢餓／護甲結算；
命令破壞仍不等於 Java 具玩家歸屬的完整事件鏈。

高跟鞋移除額外的 0.55 輸入門檻，讓低幅度控制器／觸控移動也能進入判定；
目的地由原生碰撞檢查決定，並保留速度。這仍是安全傳送適配，不是原生
`STEP_HEIGHT` 屬性。長臂的全局攻擊／挖掘距離、草叢清除仇恨、穿牆輪廓、
XP 原生拾取冷卻及純相機 roll 等差距仍明列，未用新文字或調參冒充一比一。
