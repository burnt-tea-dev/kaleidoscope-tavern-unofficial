# Recovering the native HUD

The owner's real client rejected Tavern 0.6.87 / World Liquor 0.1.51 with `Type not specified` for `hud.root_panel` and `Unknown property [modifications]`; the screenshot had no hotbar, crosshair or other normal HUD. The earlier native/script checks did not render JSON UI and did not catch this failure. Client acceptance was never passed.

The World Liquor file registered through `_ui_defs.json` used the vanilla `hud` namespace and declared a new `root_panel` containing only modifications. Registering a separate definition is not another patch to the vanilla file: the partial declaration displaced the real native root. Adding a `type` would still leave native controls absent, so this repair removes the addon declaration of the native root entirely.

Tavern 0.6.88 keeps its existing additive `hud_screen.json` hook. Its icon panel mounts `kt_optional_world_icons@$kt_world_liquor_effect_panel`; the local `|default` points to a concrete empty host panel. World Liquor 0.1.52 registers only the fully typed `kaleidoscope_world_liquor_effects.effect_panel` in its own namespace and selects it through one unique global variable. Its offset is local to the host icon panel. Neither an absent addon nor either resource order introduces a missing base or a duplicate native root. Original sprites, lifecycle data, guide entrances, optional text settings and routing remain unchanged.

The structural regression pins Mojang's Bedrock samples v1.26.50.4 commit `46ba6ea985fb5a92d79a9419198f10dda14c199d`, retains the native root type and all 29 controls, rejects the exact reported old definition shape, resolves the optional base with and without the addon, and rejects untyped standalone controls. This is a structural check, not a JSON UI renderer. Native BDS loading/restart and saved-world migration remain separate; actual client confirmation must still show the restored HUD and correct icon rendering.

References: [Mojang HUD definitions](https://github.com/Mojang/bedrock-samples/blob/46ba6ea985fb5a92d79a9419198f10dda14c199d/resource_pack/ui/hud_screen.json), [Mojang variable base references](https://github.com/Mojang/bedrock-samples/blob/46ba6ea985fb5a92d79a9419198f10dda14c199d/resource_pack/ui/stonecutter_screen.json), [Microsoft UI definitions](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/jsonuireference/examples/jsonuicomponents/ui_defs?view=minecraft-bedrock-stable).

The same client report included a pack-version error without a pack name and six ChineseFood doll warnings. All 41 active headers and all 182 server manifest files have valid three-integer versions. The version error is not yet attributed to a server file and is not claimed fixed. The doll `textures` fields are byte-identical in the pinned latest original ChineseFood 1.0.4 RP and its native BP already owns geometry/materials. The upstream warning is recorded for the Bedrock author; no third-party payload is silently patched or hidden in localization.
