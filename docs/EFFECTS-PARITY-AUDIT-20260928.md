## 對照方法與範圍

`effects-source-index-20260928.json` 索引原版明確的粒子／音效呼叫、animateTick 入口、客戶端特效與渲染類別及自訂粒子定義。**呼叫點數不是獨立特效數，建立索引也不代表所有畫面已通過驗收。** 這是酒館本體的完整顯式入口掃描，不包含沒有在此 Java 倉庫提供源碼的其他附屬，也不聲稱已重新驗證所有繼承的原版方塊破壞材質／聲音。

逐項比較：觸發條件、tick、數量、位置、速度分布、粒子建構子、壽命、貼圖幀、顏色、透明度、音高／音量、停止條件、接收玩家與交易失敗隔離。

Java 原生粒子不是只看 Mod 原始碼名稱：`tools/effects/collect_reference.py` 從官方 1.20.1 manifest 取得 client/mappings，核對 SHA-1，再取得相應建構子的 javap 指令和少量資源。官方完整 JAR、FSB 和 mappings 不放進資源包。Bedrock 文件、Mojang samples 只用於確認元件規格，不把名稱相似當成效果相同。

## 已確認存在、尚未修成一比一的差距

這些不是單純「未測試」，而是此分支仍有實作差異：

1. **微醺：** `tipsy-visual.js` 的 yaw 適配仍改變玩家朝向；Java `CameraAnglesEvent` 改的是畫面 roll。不能把「會晃」標為還原。本次不在缺少真人客戶端驗證下再次刪掉效果或強行切換相機。
2. **洞察／Vision：** 現有 `pulseVision()` 仍嘗試 `glowing`；不能把這條 Java 名稱的呼叫當成基岩版穿牆輪廓成功。新增輪廓時才播放音效的條件也依賴它。未以漂浮文字／粒子代替而宣稱一致。
3. **倒置：** 現有 Grumm 名稱適配不是 Java 的渲染事件；命名與不同實體／玩家行為必須獨立驗證。
4. **滴液著地：** Java falling dripstone water/lava 著地還生成 splash/landing lava 並播放滴水／岩漿聲；此分支仍僅到 terrain-contact expire，沒有偽裝成完整碰撞鏈。液體表面高度、向下著地與碰牆不可混為一談。
5. **粒子碰撞／渲染：** 當前 parametric+Bedrock collision 不等於 Java AABB；cloud 對近旁玩家高度的吸附、rain 著地50%消失判斷、光照數值漸變、EFFECT望遠鏡透明度與透明混合模式均未完整移植。小香薰/大型懸浮粒子無物理碰撞的原版設定則已維持。
6. **外部壓榨輸入：** 內建已知果實有正確貼圖；未知第三方輸入與木方塊碎屑還不是逐物品原版粒子。
7. **環境取樣承載：** 每玩家取樣的數學與接收對象已改正，但 Bedrock onTick 發現現有方塊可能延遲、粒子上限、世界暫停／卡頓、距離裁切與大量玩家的成本，仍不同於原生客戶端 animateTick。
8. **未重新認證的整合視覺：** 第一／第三人稱雪克杯手臂與杯蓋、投擲蓄力、座椅、酒液面、杯架／酒架實體渲染、發光字／燈串、材質與 shader 均被索引；本次沒有取得匹配的兩端真人影片，不將既有幾何數值測試冒充完整特效對照通過。
9. **其他音效位置與衰減：** 保留既有未針對性修改的通用 feedback，仍須逐一確認杯櫃／儲存／作物／拾取的 source、volume、pitch、聽者排除與距離；此輪新別名的來源雜湊一致也不等於混音器輸出完全相同。
