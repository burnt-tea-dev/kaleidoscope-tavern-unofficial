# 森羅家族相容修復：第一批候選（2026-09-29）

## 安裝邊界

本批是 **公開 Cookery 1.0.8** 的相容分支，不是「九包全面相容」正式發布。酒館 0.6.64-compat1、世界名酒 0.1.28-compat1 成對；煙火 2.8.8-compat1 是安全隔離／工具標籤候選。自己的 BP/RP UUID、module UUID、物品／方塊 ID、庫存 key 沒有改。

**Cookery 1.0.6 → 1.0.8 更換了宿主 UUID。只改我們的依賴不能遷移 Cookery 私有站點、配方學習等動態資料。** 不在舊正式世界直接替換，不同時啟用兩套 Cookery；本批先在全新測試世界或已確認使用公開 1.0.8 的世界副本驗收。自訂伺服器重綁版不屬此 profile，未修改伺服器建置腳本或正式服。

公開宿主：BP `d322809c-a51e-4742-bfc4-16d3c1491c9d`、RP `8e2c6318-2f5f-4907-aad0-31d10610e405`，版本均 `[1,0,8]`。下載檔案與 SHA256 固定在 `compat/family/cookery-host.json`（酒館與煙火分支）。

## 已改程式／資料

1. 酒館和煙火依賴改成真實新宿主身份；世界名酒同步依賴 0.6.64。沒有提高 Script API、移除 PBR、變更 HUD、指南分類或手持姿態。世界名酒 guide payload 只有協議版本變動。
2. 酒館提供 **可選** Deco 梯子相容 BP。單獨酒館保持 Java 原始六梯子配方；一起使用 Deco 時啟用此 BP，覆寫的只有酒館自己的 `minecraft:recipe_shaped` recipe ID，改由一個 Deco 人字梯換一個酒館人字梯，另提供反向 1:1 轉換。Deco 六梯子原配方保留。這是明示的共存配方，不聲稱兩個衝突原配方都維持原樣。補丁要放在兩者之上；未安裝 Deco 不啟用它。
3. 煙火死亡掉落條件讀取真實手持 ItemStack 的 `kaleidoscope_cookery:kitchen_knife` 標籤，保留四把舊刀的識別碼回退。終界龍牙刀和地獄原始砍刀實包都有此標籤；沒有為它們複製玩家檔案或改物品。掉落機率、數量、搶奪公式未改。
4. 停用煙火用自己 BP 的 `kc_station:*` 當作廚房真實庫存的牛肉砧板攔截、雞皮完成偵測。正常廚房砧板事件交回宿主，不扣料、不寫共用方塊、不假發雞皮。這是先隔離風險，**不是把額外加工功能恢復了**。
5. 停用放置油壺的私有跨包數量讀寫，HUD／模型不再拿讀不到的數量冒充 0。一般未標記的廚房油壺不取消操作；煙火特殊油桶向廚房壺灌入、特殊手持壺放置暫停。已存在煙火本地 typed marker 的壺保持資料，不自動拆、退款、搬移或清空；普通操作／破壞／爆炸事件盡量保護並給拒絕提示。這不能防止管理指令強制改方塊或其他不尊重取消的附屬。未知／壞資料不當空壺處理。

## 尚未恢復

煙火兩種 block_entity 容器在無實驗世界的錯誤仍須另做無損容器適配；本批**沒有自動打開實驗**，也不宣稱煙火設備已全部可用。跨包站點加工要等待由 Cookery 擁有資料、具操作收據的公開交易接口。手持特殊油壺的宿主資料互通也未認證。

End 1.0.1 的四款茶是茶杯，不是六品質酒瓶；Nether 1.0.1 沒有可當瓶裝酒接入的飲品，`ruby_steak` 雖使用 drink 動畫仍是菜餚。本批沒有把茶或牛排強行登記成酒。茶杯收納／調酒資料適配留後續。

第三方 Cookery 指南 mechanicsByLocale、Chinese Food 缺失原料、Immersive Eating 世界級 gamerule 副作用沒有被我們偷偷覆寫。微醺 roll、手機創造分組、總狀態數警告也未解決。

## 重現與驗收

`python tools/family_candidate.py --build`：只讀檢查 JSON、JS 語法、相對 import、精確依賴、原 UUID／PBR、以及未改檔案的帶路徑 SHA256 清單摘要，再打包完整 BP/RP；ZIP 每一項與來源比對。這不模擬玩家、不證明客戶端互動。

每份 `compat/family/candidate.json` 記錄基線提交、唯一允許修改的 runtime 檔案、其餘檔案數和整體摘要。新包不含第三方完整資產／腳本，不含任何世界或正式服資料。原公開 Release 不被覆寫。

原生 BDS 載入、原生標籤探針、真正玩家操作是三個不同證據層級。測試日誌另行提供；不能把本文件或任一靜態檢查的 PASS 當成 BDS／Android 驗收。
