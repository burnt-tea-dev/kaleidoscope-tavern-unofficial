# 待擁有者批准的重整規則

這份提案尚未生效。附件簡報 §2.2 明文要求「需擁有者批准後才能改」；
擁有者本輪也明確選擇「按整份簡報逐階段執行，規則變更另待批准」。
目前仍遵守根目錄與各倉庫 AGENTS 的既有規則。以下不是本輪部署許可申請。

## 決策一：隔離 GameTest 測試玩家

現行規則：「不得使用模擬玩家」。建議替換為：

> 只允許在獨立、可丟棄的 BDS QA 世界使用官方 GameTest 測試玩家。
> 先確認與該引擎相符的模組／實驗需求，並用真正的互動事件觀察確認會走到
> 正式 production 入口。測試玩家及其所需實驗設定不得裝入 LIVE、發布包或
> 正式存檔。結果只能標示具體 L2 引擎行為，不得稱真人輸入、聲画或 L3 驗收。
> 未能觸發相同 item-use／互動事件的場景必須保留為真人測試。

已查官方 `@minecraft/server-gametest@1.0.0-beta.1.26.51-stable` 套件存在；
peer dependencies 接受穩定版 server 2.x。套件名的 stable 指引擎版本線，
不會把 beta API 變成穩定 API。本輪未啟動該模組，尚無實際引擎可用性證據。
[Microsoft](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server-gametest/simulatedplayer?view=minecraft-bedrock-experimental)
特別說明測試玩家的 item-use 事件可能不同於真人，因此不能承諾它覆蓋整條喝酒流程。

可選：批准上述有界用法，或保留禁止並以無玩家原生場景＋真人互動完成切片。

## 決策二：切片與部署節奏

现行常設授權會在完成候選的 Git／CI／家族／存檔准入後更新 managed-server LIVE，
讓擁有者實測。建議新的工作單位是 T1、T2、W1 等垂直切片：

> 在隔離來源工作區整合一個切片的相依修補。原作 A 真值、B 守恆及該場景的
> L2 引擎證據完成後，凍結一次候選及其 D 客戶端清單，再更新指定開發測試服。
> 同一切片等待客戶端回報時不疊加無關功能；仍可修補本切片失敗與製作下一
> 切片的獨立未部署來源。另一候選不能沿用上一候選的客戶端結果。

擁有者需決定指定測試服是否繼續為 managed-server，或另提供獨立測試服。不能從簡報
自行推導「撤銷 LIVE 授權」或自動停在本機。批准前既有持續部署授權照常有效。

版本在切片整合／凍結邊界一起提升，不為每行開發變更占一個版本；一旦發布或
部署該版本，任何匯出 bytes 改變仍須新身份。保留 canonical Git、私有邊界、
發佈／候選／停服備份／遷移／安裝邊界的必要完整性檢查。family_guard 僅證明
准入與安裝來源；A–D 功能／視覺結果各自記錄。文件工作不換包、不重啟。

## 決策三：本輪 Java 比較基準

建議 T1/T2/W1 固定 Minecraft1.21.1 NeoForge：Tavern1.2.0（CF8350856）
及 World Liquor1.1.11（CF9066406），以已核驗來源為準。兩個 Forge 分支及
26.1.2 新分支保留為另行適配需求，不能冒充已同時還原。

> 一個切片期間固定來源，原作向量與參考聲画使用同一 loader／Minecraft。
> 上游仍唯讀偵測；新版只記錄待審查，不會自動改切片基準或安裝。
> 完成切片後再明確決定是否開新版適配工作。

這是取代「每次修補先追所有分支最新版」的工作節奏提案。批准前仍保留現行
六小時查核，並明列未適配新版；不得永久把舊 fixture 標成最新版。

## 倉庫安排建議

先保留三個公開 canonical 倉庫與已核驗私有整合倉庫，共用家族 CI 和配套鎖。
先修 README／驗證入口與資料契約，再判斷 monorepo 是否有收益。World Liquor
已有部分純內容註冊與宿主生命週期委派，沒有必要先全量重寫。

任何 monorepo 遷移另行批准；必須保留原 UUID、獨立發佈、原授權與歷史。
第三方私有完整腳本不進公開 monorepo，也不以公開 tag 規則強迫公開私有 addon。

## 不需要規則變更即可繼續的工作

- 整理现行 README／CHANGELOG、維護單一 PARITY-MATRIX 與 BUGS。
- 補齊世界名酒發布包既有授權聲明，走正常新版本／PR／CI 配套。
- 萃取已核验原作資料，將有效 Java 向量接到正式純函式並做有界變異檢查。
- 改造永真斷言、分離品質測試與發佈完整性前置，保留有效守恆／保存測試。
- 對未合併的模型／動畫有效差異做新鮮來源移植，準備真客戶端比較場景。

這些工作可依現行授權執行；GameTest 玩家、部署新節奏與永久單一 Java 分支
則須等對應決策。沒有將尚未批准的條文写入 AGENTS。
