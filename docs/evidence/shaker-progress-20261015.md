# Shaker progress lifetime repair

The current client report distinguishes visible three-ingredient slot graphics from a missing progress bar while shaking animation and sound work. This is evidence of a progress-specific failure; it does not establish a foreign HUD conflict or a broken mount.

T168's shipped progress packet expires after 200 ms, while the actual sender permits the same progress value to wait ten ticks before a heartbeat. A four-to-nine-tick interruption therefore leaves no progress graphic even though no refresh is yet due. Slots already retain their image for 600 ms. T169 applies the same 600 ms lifetime to progress and explicitly disables animation fast-forward on the packet that owns the expiry alpha and the cursor image that owns the offset animation. The animation still takes one Java integer-pixel step and holds; it does not advance through unobserved server ticks. END still replaces the owned instance immediately.

The fixed Mojang v1.26.50.4 source uses the fast-forward opt-out on [HUD auto-save](https://github.com/Mojang/bedrock-samples/blob/46ba6ea985fb5a92d79a9419198f10dda14c199d/resource_pack/ui/hud_screen.json#L2051), [Store animated images](https://github.com/Mojang/bedrock-samples/blob/46ba6ea985fb5a92d79a9419198f10dda14c199d/resource_pack/ui/store_common.json#L1528) and [Game Tip factory images](https://github.com/Mojang/bedrock-samples/blob/46ba6ea985fb5a92d79a9419198f10dda14c199d/resource_pack/ui/game_tip_screen.json#L20). These are native property examples, not proof that fast-forward caused this client's missing bar.

The targeted source regression regenerates a temporary old-policy UI through the actual Python generator and compares its complete output with the shipped JSON. It also joins the shipped lifetime to the actual sender's unchanged-value cadence across ticks four through nine, preserves immediate active updates and END, and verifies the cursor's bounded hold. Existing visibility/motion checks retain all 112 progress states, Java coordinates, texture references and creation pruning. These are source/configuration checks; no simulated player, native renderer or client recovery is claimed. Java 111-tick gameplay, recipes, sound, textures, factory capacity, channel and namespace remain unchanged.
