# 酒館家族指南固定規範

使用者於 2026-09-27 明確要求。後續版本與附屬必須遵守；未取得使用者改版要求，不得攤平、合併大入口或自行改名。

2026-09-27 補充要求：小分類只有一個條目時，按鈕直接顯示該物品名稱並開啟內容；返回上級分類。多條目保留列表。不得為單條目多加一層點擊。

## 固定入口與順序

| 大入口 | 小入口 | 獨立條目 |
|---|---|---|
| 釀造設備 | 酒桶釀造、壓榨與接汁、雪克杯調酒、冷凍製作 | 每種設備的使用方法 |
| 釀酒百科 | 酒館本體、附屬配方（本體在前） | 每種酒桶產物；同一產物的多種配方放在同一條目 |
| 調酒百科 | 酒館本體、附屬配方（本體在前） | 每種雪克杯產物；材料以實際顏色條件為準 |
| 材料與種植 | 葡萄與藤架、果汁、調酒材料 | 普通／冰／金葡萄、青提各自說明；每種果汁、可樂、湯力水各自條目 |
| 收納與實用 | 裝酒容器、實用工具、酒櫃、酒架與杯架 | 每種容器、工具、酒櫃、酒架各自條目 |
| 裝飾與家具 | 吧檯與桌子、高腳凳、沙發、燈飾、掛畫與唱片、立式告示牌與黑板、香薰 | 每種物品獨立條目，不拼成一頁長清單 |
| 食物 | 冰櫃食品、工作台食品 | 每種可製作的食物 |

2026-10-02 使用者追加要求：酒館需自帶獨立指南，且本體不再強制依賴 Cookery。獨立書與可選 Cookery 入口共用同一份內容及「大入口 → 帶圖示與條目數的小入口 → 物品條目」結構。
未安裝提供該內容的附屬時隱藏空的小入口，七個大入口仍保留。

## 條目與配方

- 用法、製作方法、成品效果放在同一物品條目；不得另建只有配方的重複頁。
- 設備頁說明操作，不列所有產物的配方；食物與飲料保留全部製作方法；Cookery 入口使用既有條目／配方介面，獨立指南呈現相同配方資料，不從攤平的材料陣列猜測合成格。
- 家具、設備的工作台合成由原版配方書處理，指南不能留下不存在的「配方卡」指示。
- 不把可樂、湯力水、果汁列為雪克杯雞尾酒。青提是採收副產物，不能描述成可獨立種植的藤蔓。
- 本體與附屬使用同一份 `guide-navigation.js`；附屬提供素材、名字、配方、操作說明，不另造分類介面。
- 小入口以本體／附屬分組，順序固定；不依賴廚房按物品名排序的列表來保證來源順序，也不改其他附屬的排序。
- 廚房 v1 最多接收 32 個分類（包含大入口）、只支援一層父分類。現有組合共 31 個分類。不得直接新增第 33 個而讓宿主靜默丟棄。
- 繁中、簡中、英文均須完整，圖示使用條目對應素材。

## 黑板／立式告示牌

保留 Java 的靠左、置中、靠右及舊存檔預設置中／靠上。依使用者 2026-09-27 最新要求，擴充左右對齊（段末行靠左）、分散對齊，以及垂直靠上／置中／靠下；新增模式是本移植版擴充。小黑板最多 11 行，每行最多 10 個半角或 7 個全角字；混排同時受字數容量與 63 字型像素寬度限制。大黑板維持 Java 232 像素寬度及 11 行，立式告示牌維持 55 像素及 8 行。新編輯超出容量不得靜默截斷；應拒絕此次儲存並提示，保留舊文字。

基準：KaleidoscopeMods/KaleidoscopeTavern `c4ec1880bd44cf3139d3ba744ab30bb379cf1416`。Java 字型和基岩移植字型並不完全相同；本規範鎖定對齊規則，不宣稱逐像素一致。

## 發布檢查

`tools/check_guide.mjs` 必須呼叫獨立驗收規範 `tools/guide_contract.mjs`。世界名酒以實際擴充註冊資料再次驗證完整指南、配方覆蓋、傳輸往返、語系及宿主容量。只驗證原始 JSON 不足；隔離 BDS 中還要確認廚房實際接收的章節保有父子分類與全部條目。

禁止模擬玩家測試。靜態資料驗證及無玩家 BDS 接收測試不能標記成客戶端 UI／操作驗收通過。
