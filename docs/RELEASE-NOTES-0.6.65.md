# 0.6.65 beta 1

修復東西朝向酒櫃／酒架取放的左右鏡像（來源：PR #105，經反事實回歸驗證）。

- **觸控路徑靜默回退**：先前觸控（非 hotbar 模式）會先算出正確瞄準點並寫入 `used=aim` 日誌，卻在組裝回傳值時讀取不存在的引擎命中面而拋錯，被大範圍 catch 吞掉後改用原始鏡像座標選格——這解釋了「日誌顯示 aim 但實際仍左右相反」。現在解析與觀測完全解耦：瞄準點一旦算出就一定會被採用，日誌或選配屬性的失敗都不再能丟棄它，並區分解析錯誤與日誌錯誤。
- **內縮選取盒隨朝向旋轉**：傾斜酒架、圓周酒架、吊掛杯架的選取盒並非整格，先前未套用方塊的朝向置換，導致東西向的瞄準點本身就落在鏡像位置。現在由方塊定義的置換矩陣推導有效盒（整數四分之一轉，避免三角函數誤差），並以獨立資產斷言測試防止漂移。
- **診斷升級**：`[Tavern storage aim]` 改為 schema 2，記錄真正回傳的 `resolved`、route、facing、`used` 與 fallback 原因；玩家加上 `kaleidoscope_tavern:debug_storage_aim` 標籤可持續記錄，不限前 12 次。

驗證：事件到背包的反事實回歸 210/210（修復前為 151/210，失敗項即為觸控 hotbar=false 與交接重播案例）、瞄準幾何 34/34、foundation 231/231、tap 19/19、pickup 7/7 + 283/283、mechanics 8/8、靜態檢查通過。**真實手機／平板觸控驗收仍未完成**——測試替身與 CI 綠燈不構成客戶端驗收。
