# Exact integration source admission

The retained-runtime consumer distinguishes a reviewed four-file integration
from a dependency-only release. An integration cannot impersonate the older
profile or substitute its current tree for the historical anchor.

The 1.0.64 profile pins two opaque SHA256 policy inputs: the reviewed runtime
contract and a small captured Fishing 1.3 salt recipe input. These inputs remain
in the owning private source. No private pack, author archive, host report or
world is included in this repository. Unknown versions or different policy
hashes fail closed and need a separate review.

The consumer verifies a clean committed source, the actual Git predecessor and
its tree, identical inventories, exactly two manifests and two HUD files, all
368 conserved files, and each reviewed before/after hash. It reconstructs the
manifest changes and runs the original P62 dependency-only and P58 component
rules against immutable historical bytes. Existing P58/P62 and current-functional
entry points retain their existing rules.

Fishing admission covers the captured water-bucket/salt-bucket/sea-salt recipes
and equivalence of the retained ChineseFood-salt alternative. It does not prove
an original author archive, latest release, event listener behavior, rendering,
saved-world loading, or performance. Source admission leaves those acceptance
flags false.

Run `python -m unittest discover -s tools/family_update -p 'test_*.py'` and
`python tools/test_current_host_profiles.py`. The exact-integration suite creates
owned synthetic Git histories and calls the producer and consumer in separate
processes. Only the catalog and policy hashes are replaced with hashes of owned
fixture data. Validation functions, Git reads, runtime inventories and producer
results are not mocked. Positive P58/P62/P64 and negative kind, anchor/tree,
version, fifth edit, HUD hash, added/removed file, rehashed helper, Fishing source
and dirty-source cases run in the normal always-on family CI suite.

The impact classifier marks the covered family tooling as source-only. Its
regressions and family suite still run unconditionally; mixed runtime changes
continue to select the complete runtime jobs. No engine or world is started by
these source tests.
